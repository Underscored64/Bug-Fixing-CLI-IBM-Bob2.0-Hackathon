# bugfix — Bug Explainer powered by IBM Bob

A CLI tool that takes a traceback/error message plus the relevant code, and returns:
- the **likely root cause** of the bug, explained clearly
- one or more **suggested fixes**, with code snippets
- a **confidence level** on the diagnosis (high / medium / low)

Built for the **IBM Bob 2.0 Hackathon** (lablab.ai, September 25–27, 2026).

## The problem

Understanding a traceback and finding the right fix takes time, especially for a
junior developer or when facing an unfamiliar codebase. This tool automates that
first diagnosis step to speed up debugging.

## How it works

1. The user provides a code file and a traceback (or pastes it interactively)
2. The script builds a structured prompt requesting a strict JSON response
   (cause, fixes, confidence)
3. The prompt is sent to **IBM Bob**
4. The response is parsed and displayed in a readable format in the terminal

## Integration with IBM Bob

`bugfix.py` is built to call Bob through its non-interactive CLI
(`bob run --format json`, see `call_bob()` in the code) as a subprocess.

**Note on this submission:** the `bob` CLI was not available in the PATH of the
development environment used during the hackathon. The pipeline (prompt building →
Bob call → JSON parsing → display) was therefore validated manually through Bob's
chat panel in the IDE, using the exact same prompt generated by `build_prompt()`.
See the screenshot below. The CLI integration code is fully implemented and ready
to run as soon as `bob` is available in the PATH.

## Usage

```bash
python3 bugfix.py --code path/to/file.py --traceback path/to/error.txt
```

Or by pasting the traceback directly:

```bash
python3 bugfix.py --code path/to/file.py
```

## Example

**Tested code** (`bug_test.py`):

```python
def diviser(a, b):
    return a / b

print(diviser(10, 0))
```

**Traceback provided:**

```
Traceback (most recent call last):
  File "bug_test.py", line 4, in <module>
    print(diviser(10, 0))
  File "bug_test.py", line 2, in diviser
    return a / b
ZeroDivisionError: division by zero
```

**Bob's response:**

```json
{
  "cause_probable": "The 'diviser' function performs a division without checking whether the divisor is zero. Passing b=0 triggers a ZeroDivisionError because Python does not allow division by zero.",
  "corrections": [
    {
      "description": "Check the divisor before dividing and raise an explicit ValueError",
      "code_corrige": "def diviser(a, b):\n    if b == 0:\n        raise ValueError(\"Divisor 'b' cannot be zero.\")\n    return a / b"
    },
    {
      "description": "Return None (or float('inf')) if b is zero, for non-blocking behavior",
      "code_corrige": "def diviser(a, b):\n    if b == 0:\n        return None  # or float('inf') depending on business context\n    return a / b"
    },
    {
      "description": "Catch the exception at the call site instead of inside the function",
      "code_corrige": "try:\n    print(diviser(10, 0))\nexcept ZeroDivisionError as e:\n    print(f\"Division error: {e}\")"
    }
  ],
  "confiance": "haute"
}
```

## Requirements

- Python 3.10+
- `pip install -r requirements.txt`
- The `bob` CLI installed and authenticated (`BOB_API_KEY` environment variable)
  for automated CLI usage

## Future improvements

- Multi-language support (currently Python-focused)
- Automatic application of the chosen fix (direct file patching)

- CI/CD integration (pre-commit or pre-push hook)
